# 二开改动与验证

当前版本：`0.17.4-greeting.5`，构建号 `46`，Windows x64。

## 改动范围

本分支在上游 GeekGeekRun 的自动开聊基础上增加：

1. 在设置页面选择 PNG / JPG 图片及填写固定文字。
2. 首次开聊时先发图片，再发固定文字。
3. 图片和文字分别确认，记录消息 ID 和处理进度。
4. 在本地单独保存图文进度，不修改原有业务数据库表结构来存储此进度。
5. 启动时核对未完成发送，与本地历史开聊记录共同处理防重复需求。
6. 使用独立程序名称、安装目录、Electron 缓存目录和后台连接文件。
7. 同步纯中文编辑器输入状态，等待已启用的发送按钮，避免按钮尚未可用时点击。
8. 残留任务锁的进程存活检查，保留活跃任务的并发保护。
9. 两套人工核对窗口，以及选择后恢复当前任务的流程。

本分支没有重写上游职位筛选及其他业务模块；保留上游界面的其他功能，不将它们归为本分支新创功能。

## 本版两套人工核对

### 图片二次确认失败

- 图片成功：只补文字。
- 图片不存在：重走先图后文。
- 图片转圈或显示失败：结束当前任务并保留进度，等待人工处理。

### 发送结果对账不确定

- 图文都成功：标记完成，继续后续对象。
- 只有图片成功：只补文字。
- 都未发送：重走先图后文。

两种窗口均支持定位当前聊天；关闭窗口或按 Esc 会结束当前任务并保留进度。人工选择前后检查账号和对象；同一个选择不能授权进程重启后的无限重发。文字的服务器确认失败使用整套图文核对窗口，避免误用图片专属按钮。

## 验证结果

发布前在 Windows 上执行 45 项回归测试，全部通过，包含：

- 图片先于文字、完成后不重复发送。
- 关闭新增开关后不触碰这套发送流程。
- 发送结果不确定时阻止盲目重试。
- 账号及对象检查、历史会话和不同账号的数据隔离。
- 残留锁和仍在运行的进程锁处理。
- 真实 Chrome 中的中文、多行和 emoji 输入、不同草稿保护、延迟启用及禁用按钮处理。
- 两种人工核对选项的恢复、旧消息 ID 清理、文字快照保留及再次中断。
- 真实 Electron 中六个选项、关闭窗口、打开聊天和渲染进程隔离检查。

还验证了生产构建、NSIS 安装包生成、打包后程序和实际安装后程序的启动、版本号、设置入口及隔离数据库读取。发布时检查归档包含两套核对窗口代码，且不把旧版安装包嵌套打入新包。

覆盖安装前后曾对本机原有业务数据库、配置、登录文件和发送进度进行内容摘要比对，确认升级保留数据。相关真实数据、备份和登录信息没有纳入本仓库或发布资产。

## 边界与已知限制

- 上游全量 TypeScript 检查仍有已有诊断；本次修改的图文功能文件没有新增类型诊断。生产构建通过不等同于整个仓库类型检查通过。
- 发布验证针对 Windows x64，其他系统没有同等验证过的安装包。
- 测试没有使用用户账号向真实招聘者额外发送测试消息。
- 真实网页结构、平台发送状态和限制可能变化，未来可能需要继续适配。
- 人工核对以用户确认的实际聊天状态为依据，错误选择可能引起错误重试。
- 本地数据不会跨设备自动同步，也没有自动合并两台电脑投递历史的功能。
- 保留原有数据库和未完成状态是防重复的重要前提，不建议清空数据解决发送异常。
- 上游大模型配置页面保留了一个第三方共享示例预设，本分支没有新增或嵌入用户个人服务密钥；先图后文和人工核对功能不依赖该模型服务。
